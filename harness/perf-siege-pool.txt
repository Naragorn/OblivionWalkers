# gate shut until it is over - "1. ja"). A siege the player comes to would
# take its walkers from a pool in the ESP, like the gate guards, since
# PlaceAtMe's actors stay in the save for good. The pool's references are
# persistent and initially disabled; what so many of them cost the game, and
# whether the engine puts them on its process lists (where the plugin's walk
# of the walkers would meet them), is not known. Two runs of this scenario,
# the same save and the same path: the deployed ESP, then one written with
# `tools/esp-write.py --test-walker-pool 30` (30 a city, 240 walker
# references in the holding cell). The game's prison (ImperialDungeon01),
# the player held and in god mode, watched for 90 s with OBVR's profiler on;
# OBVR's tools/perf-phases.py cuts the capture by the marks:
#   python3 tools/perf-phases.py <run> prison p30 p60 p90 --events scene_pass
# OblivionWalkers.log's "Walk: N walkers on the process lists" lines tell
# whether the disabled pool is on the lists.
#
# Result 2026-10-26 20:47 and 20:51 (artifacts/hand-script/perf-siege-pool/,
# Linux, the Beyond at 75 Hz, dual pass, one run each): no cost seen.

# ms, 0.1-0.2 % over 20 ms. "Walk: 0 walkers on the process lists" in both:
# the disabled pool is not on them. The ESP loaded in both (its walkers,
# guards and editions found); the 240 references themselves were not looked
# up, and what they cost on a cell change or a load is not measured.
