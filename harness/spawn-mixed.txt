# Ten walkers at once are one look (Nadi, Windows, 2026-10-27: "wenn 10
# walker auf einmal spawnen dann ist es immer der selbe typ aus unserem
# pool, aber es sollten 10 unterschiedliche sein"). Read in the ESP: the
# variant list WalkersZombieVariant (0x805) holds each walker with a count
# (1..10, ReplaceLogic.h SpreadCount), so a draw picks one walker and the
# engine makes count copies of it. The probe: whether an entry that points
# at a second list (every walker once) with a count is drawn anew for each
# of the count - `tools/esp-write.py --test-nested-variant`, Linux install
# only, the deployed ESP put back after.
#
# The variant list is placed four times in the hall (player.placeatme
# 11000805, the ESP at 11 in the Linux load order), the player in god mode.
# The roster at each mark lists the bases and how many of each: one base
# per placement - one look per draw; several bases from one placement of
# count above 1 - drawn anew per copy. Run once with the deployed ESP (the
# control) and once with the probe's.
#
# Results 2026-10-27 (artifacts/hand-script/spawn-mixed/), Linux: 14:41
# deployed ESP - one base per placement (3, 8, 3, 2); 14:44 nested list,
# flags 0 - still one base each (2, 9, 9, 3); 15:37 nested list with LVLF 2
# ("calculate for each item in count") - 4, 4, 6, 3 walkers, all different
# bases. The ESP is built so since (WalkersAnyWalker 0x94A); this scenario
# with the deployed ESP now expects the mixed result.
#
# Runs on OBVR's harness, from the OBVR folder:
#   python3 tools/hand-script-run.py ../OblivionWalkers/harness/spawn-mixed.txt --headless \
#       --artifact-root ../OblivionWalkers/artifacts/hand-script

expect HandScript: finished
